# Fine-Tuning LLMs for Self-Refining Reasoning

Can a small language model learn to **check its own work**? This project fine-tunes small Qwen3.5 base models (2B and 4B) to write two attempts at a math problem, **critique** them, and then give a final answer. We compare this "self-refining" model with the untouched base model and with conventional chain-of-thought (CoT) fine-tuning on the MATH-500 benchmark, using the same problems, the same compute and significance tests.

**Headline result (Qwen3.5-4B-Base, MATH-500):**

| Model | Accuracy |
|---|---|
| Base model | 68.2% |
| CoT fine-tuning (conventional reasoning) | 71.6% |
| **Self-refine fine-tuning (ours)** | **75.4%** |

Self-refinement beats both the base model (p = 0.0002) and CoT fine-tuning (p = 0.048, McNemar test). When its two attempts disagree and only one is right, the model picks the right one **83%** of the time.

---

## 1. Problem statement

> Fine-tune a pretrained language model to generate multiple reasoning chains, reconsider its initial approach, and produce a more refined final answer. Evaluate the improvement in reasoning performance and demonstrate the difference between conventional and self-refining reasoning.

Language models usually answer in one pass: whatever the first chain of reasoning says is the answer. Small models make many mistakes this way, and research has shown that simply asking a model to "check your answer" often does not help, because the model cannot tell its right answers from its wrong ones. This project asks whether that ability can be **trained in**: if we show a small model many examples of "two attempts, a critique that finds the mistake, and the corrected answer", does it learn to actually reconsider?

## 2. What the model learns to write

Every training example (and every answer at test time) has this shape:

```
[Question] A math problem
[Answer 1] first attempt, step by step ... \boxed{...}
[Answer 2] second attempt, step by step ... \boxed{...}
[Review] short critique: which attempt is right, and the exact step where the other goes wrong
[Final answer] ...
```

The two attempts are the model's **own** attempts (generated by the same base model before training), so it learns to critique the kind of mistakes it really makes.

## 3. Method

| Step | What happens | Notebook |
|---|---|---|
| 1. Baseline | Run the untouched base model on MATH-500 | `01_baseline_math500` |
| 2. Attempts | For each of ~7,500 MATH training problems (MATH-500 removed), the base model writes 4 attempts; each is graded with `math_verify` | `02_generate_chains` |
| 3. Pairs | Pick two attempts per problem: **correction** (wrong then right), **keep** (right then wrong) and **agree** (both right) | `03_select_pairs`, `03_select_pairs_4b` |
| 4. Reviews | A larger **teacher** model reads both attempts (and the known correct answer) and writes the critique in the student's voice. Reviews are kept only if they end in the correct answer and never mention being told the answer | `04_generate_reviews` (Qwen3.5-9B), `04b_generate_reviews_qwen27b` (Qwen3.8-27B) |
| 5. Training files | Build three versions on the **same problems**: Review (method), Refine (ablation: rewrite the whole solution instead of critiquing) and CoT (baseline: one correct chain) | `05_build_sft_data`, `05b_build_sft_data_27b`, `05_build_sft_data_4b` |
| 6. Fine-tuning | LoRA fine-tuning with TRL `SFTTrainer`; loss only on the answer part | `06_train_sft` |
| 7. Evaluation | Merge the adapter, generate on MATH-500 with vLLM (greedy), grade with `math_verify` | `07_evaluate` |
| 8. Analysis | Tables, self-correction metrics, McNemar significance tests, examples | `08_results_analysis` |

**Training settings:** LoRA r=16, alpha=32 on attention, linear-attention and MLP projections; learning rate 1e-4 (cosine); 2 epochs; batch 1 x 16 gradient accumulation; max length 2048; completion-only loss. 2B trained in float32 weights with fp16 mixed precision; 4B in float16 weights (to fit on one T4).

**Evaluation settings:** MATH-500, greedy decoding, up to 3072 new tokens, `repetition_penalty=1.1`, answers graded with `math_verify`.

**Compute:** everything ran on free Kaggle GPUs (2x NVIDIA T4). The 27B teacher ran in 4-bit (GPTQ) across both T4s.

## 4. Results

### 4.1 Qwen3.5-2B-Base

| Model | Accuracy | Final answer vs first attempt | Picked right attempt* |
|---|---|---|---|
| Base 2B | 55.6% | - | - |
| CoT fine-tuning | 57.4% | - | - |
| Refine (rewrite the solution) | 54.6% | -2.2 | 65.4% |
| Review, 9B teacher | 59.8% | +2.4 | 71.3% |
| **Review, 27B teacher** | **61.2%** | **+3.8** | **76.6%** |

### 4.2 Qwen3.5-4B-Base

| Model | Accuracy | Final answer vs first attempt | Picked right attempt* |
|---|---|---|---|
| Base 4B | 68.2% | - | - |
| CoT fine-tuning | 71.6% | - | - |
| **Review, 27B teacher** | **75.4%** | **+7.2** | **83.1%** |

\* When the two attempts disagree and exactly one is right, how often the final answer is the right one. Guessing would give 50%.

### 4.3 Significance (McNemar test on the 500 problems)

| Comparison | p-value | Significant (p < 0.05)? |
|---|---|---|
| 4B Review vs 4B Base | 0.0002 | Yes |
| **4B Review vs 4B CoT** | **0.048** | **Yes** |
| 4B CoT vs 4B Base | 0.078 | No |
| 2B Review (27B) vs 2B Base | 0.009 | Yes |
| 2B Review (27B) vs 2B Refine | 0.002 | Yes |
| 2B Review (27B) vs 2B CoT | 0.079 | No |
| 2B Review (27B) vs 2B Review (9B) | 0.53 | No |

### 4.4 Accuracy by difficulty (4B)

| Model | Level 1 | Level 2 | Level 3 | Level 4 | Level 5 |
|---|---|---|---|---|---|
| Base 4B | 86.0 | 87.8 | 82.9 | 68.0 | 38.1 |
| CoT 4B | 97.7 | 88.9 | 82.9 | 71.1 | 43.3 |
| Review 4B | 90.7 | 91.1 | 88.6 | 72.7 | **52.2** |

## 5. Findings

1. **Self-refinement can be trained.** Teaching the model to critique its own two attempts significantly improves over the base model at both 2B and 4B.
2. **It beats conventional reasoning at 4B.** 75.4% vs 71.6% for CoT fine-tuning on the same problems, statistically significant. At 2B the gap is in the same direction but not significant.
3. **The model really reconsiders.** Its final answer is better than its own first attempt (+7.2 points at 4B), it fixes far more answers than it breaks (50 vs 14 at 4B), and it picks the right attempt 83% of the time.
4. **Critiquing works, rewriting does not.** The Refine ablation, which rewrites the whole solution instead of writing a critique, is worse after reconsidering than before (-2.2 points).
5. **A better teacher helps.** Reviews from Qwen3.8-27B point to the exact wrong step more often than reviews from Qwen3.5-9B, and the trained model improves (59.8% to 61.2%), though this difference alone is not significant.
6. **The gains are largest on the hardest problems.** Level 5: 52.2% (Review) vs 43.3% (CoT) vs 38.1% (base) at 4B.
7. **Bigger models reconsider better.** Self-correction gain grows from +3.8 (2B) to +7.2 (4B), and correct picks from 77% to 83%.

## 6. Limitations (stated honestly)

- **Compute cost.** The review model writes two attempts plus a critique, about 2.3x more tokens than CoT. Majority voting over 4 samples of the 4B base model reaches 72.8%; Review 4B is ahead (75.4%) but that difference is not significant (p = 0.19).
- **One benchmark.** All results are on MATH-500 (competition math). Other domains were not tested.
- **The 4B CoT win is close to the threshold** (p = 0.048); a different random seed could move it either way.
- **The teacher sees the correct answer** while writing reviews. This is standard for training data, but the reviews are therefore "better informed" than anything the student can write at test time.

## 7. Project history

1. **v1 (archived in `archive_v1_phi2/`):** Phi-2 trained for CoT and DCoT (multiple chains). Generations never stopped. Root cause found later: the training examples never ended with an end-of-text token, so the model never learned to stop. Every example in v2 ends with exactly one EOS token.
2. **v2, 2B:** rebuilt from scratch on Qwen3.5-2B-Base with the model's own attempts. First evaluation showed looping outputs; adding `repetition_penalty=1.1` fixed most of them.
3. **Teacher upgrade:** replaced the 9B teacher with Qwen3.8-27B (4-bit) and retrained the review model.
4. **Scaling to 4B:** repeated the full pipeline with Qwen3.5-4B-Base, including its own attempts, reviews, and both Review and CoT training.

## 9. Reproducing

1. Run notebooks 01, 02, 04/04b, 06 and 07 on Kaggle (GPU T4 x2, internet on). Notebooks 03, 05 and 08 run on a laptop.
2. For the 4B model set `model_name='Qwen/Qwen3.5-4B-Base'` and `model_tag='qwen4b'` (and `train_dtype=torch.float16` in 06).
3. Main packages: `transformers==5.18.0`, `peft==0.21.1`, `trl==1.14.1`, `vllm`, `math-verify`, `datasets`.

**Model weights:** the LoRA adapters are not stored in git (size). They are kept locally under `models/` and will be published separately.
